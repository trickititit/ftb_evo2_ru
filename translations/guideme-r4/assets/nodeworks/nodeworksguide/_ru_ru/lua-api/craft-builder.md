# <a name="craftbuilder" />РемеслоСтроитель

`CraftBuilder` — это то, что [`network:craft`](network.md#craft) возвращает назад. Он представляет собой проект, который сеть запланировала, но еще не осуществила. По умолчанию результат оказывается в [Сетевое хранилище](../nodeworks-mechanics/network-storage.md), когда поделка завершается. Если вместо этого вы хотите обратный вызов, используйте цепочку `:connect(fn)`.

Создание может завершиться в один и тот же тик (ванильные рецепты, собранные из хранилища) или занять много тактов (все, что проходит через обработчик обработки [`network:handle`](network.md#handle) или многоэтапное дерево крафта). В любом случае API конструктора один и тот же.

> **Примечание:** `network:craft` всегда возвращает строителя, даже если крафт > невозможно спланировать (нет рецепта, отсутствуют ингредиенты, нет процессора для крафта). Ошибка > проявляется через обратный вызов `:connect` как `nil`.

## <a name="default:-stores-the-result" />По умолчанию: сохраняет результат

Если вы ничего не связываете, готовые элементы автоматически помещаются в сетевое хранилище с использованием обычных правил приоритета [Карта памяти](../items-blocks/storage_card.md) и [`network:route`](network.md#route). После этого вы можете запросить их через `network:find`, как и все остальное в пуле.

<LuaCode>
```lua
-- fire-and-forget: craft 16 torches, they land in storage
network:craft("minecraft:torch", 16)
```
</LuaCode>

## <a name="connect" />подключить

Передает готовые элементы обратному вызову **вместо** автоматического сохранения. Вызов `:connect` выводит построитель из поведения по умолчанию, среда выполнения не сохраняет автоматически, результат принадлежит обратному вызову.

Аргументом обратного вызова является `ItemsHandle?`, [ПредметыРучка](items-handle.md) в случае успеха или `nil` в случае неудачи. Всегда проверяйте перед использованием.

<LuaCode>
```lua
local oven = network:get("oven")
network:craft("minecraft:bread", 4):connect(function(items: ItemsHandle?)
  if not items then
    print("bread craft failed")
    return
  end
  oven:insert(items) -- finished bread goes straight into the oven
end)
```
</LuaCode>

Обратный вызов срабатывает один раз, когда корабль разрешается. Виды отказа, которые отображаются как `nil`:

- План провалился: нет рецепта, недостающих ингредиентов, нет крафтового процессора в сети.
- Тайм-аут асинхронности: обработчик обработки не доставил выходные данные.
- Процессор не в сети: процессор крафта был сломан или удален в процессе создания.

В каждом случае сбоя среда выполнения также освобождает часть буфера ЦП обратно в сетевое хранилище, чтобы элементы не зависали.

### <a name="you&#x27;re-responsible-for-moving-the-items" />Вы несете ответственность за перемещение предметов

Дескриптор, который получает обратный вызов, представляет собой **живую ссылку на элементы, все еще находящиеся в буфере процессора крафта**. Вызов `card:insert(items)`/`network:insert(items)` выводит их из буфера в пункт назначения.

Все, что еще находится в буфере после возврата обратного вызова, **отбрасывается на позицию ЦП** и регистрируется ошибка терминала. Контракт таков: «Вы взяли ручку, вы несете ответственность за перемещение предметов», неспособность слить воду — это не молчание.

<LuaCode>
```lua
local chest = network:get("ore_chest")
network:craft("minecraft:iron_ingot", 8):connect(function(items: ItemsHandle?)
  if not items then return end
  if not chest:insert(items) then
    -- chest full: fall back to network storage instead of dropping
    network:insert(items)
  end
end)
```
</LuaCode>

Это намеренно отличается от автоматического сохранения, которое всегда маршрутизируется через сетевые карты памяти (и выбрасывается в мир только в том случае, если каждая карта памяти отказывается). При использовании `:connect` обратный вызов решает, куда направить элементы, и среда выполнения доверяет вам их перемещение.

> **Примечание.** Ошибки, возникающие внутри обратного вызова, регистрируются в терминале, но не удаляют остальную часть вашего скрипта.

## <a name="when-connect-runs-synchronously" />Когда подключение выполняется синхронно

Ванильные рецепты, ингредиенты которых уже находятся в хранилище, завершаются в тот же момент. Обратный вызов по-прежнему выполняется по тому же пути, всего на один такт позже, чем вызов `:craft`, так что `:connect` имеет возможность зарегистрироваться до разрешения. Вам не нужно указывать это в особом случае, API ведет себя одинаково для синхронных и асинхронных проектов.

<LuaCode>
```lua
-- works the same whether the craft is instant or takes 30s of smelting
network:craft("minecraft:iron_ingot", 8):connect(function(items: ItemsHandle?)
  if items then chest:insert(items) end
end)
```
</LuaCode>
