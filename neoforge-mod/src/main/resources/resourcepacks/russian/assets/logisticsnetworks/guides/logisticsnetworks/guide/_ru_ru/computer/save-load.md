# Сохранение и загрузка сетей

Компьютер может записать настройку узла всей сети в файл `.lnet` на диске и прочитать его позже. Это позволяет вам хранить библиотеку сетевых схем — создавать резервные копии рабочих настроек, копировать их в другой мир или передавать кому-то другому.

Файл `.lnet` представляет собой текстовый снимок. Для каждого узла в сети он сохраняет **метку** узла, является ли он **видимым**, а также полную **конфигурацию буфера обмена** узла (все 9 каналов, их режимы, фильтры и обновления). Он **не** хранит позиции блоков — файл — это рецепт настройки узлов, а не копия мира.

## Где живут файлы

Сохраненные сети входят:

```
config/logistics-network/networks/
```

внутри папки вашего экземпляра. Каждый файл назван в честь сети (обработано — только буквы, цифры, `.`, `_`, `-`; обрезано до 48 символов). Вы можете копировать эти файлы между экземплярами или делиться ими, как и любым другим файлом.

## Сохранение сети

1. Подключите сеть от [Сетевой каталог](network-directory.md).
2. На панели подключенной сети используйте **Основное взаимодействие** для **СОХРАНИТЬ СЕТЬ** (`Write .lnet file`).
3. Компьютер немедленно экспортирует смонтированную сеть и сообщает о результате на этой панели.

Компьютер пишет `<network-name>.lnet`. Повторное сохранение с тем же сетевым именем **перезаписывает** существующий файл.

### Каждому узлу нужна метка

Экспорт работает только в том случае, если **каждый узел в сети имеет метку**. Метки — это то, как файл сопоставляет сохраненную конфигурацию с узлом. Отсутствующие метки блокируют экспорт и вместо файла выдают эту ошибку:

- `Missing labels: X nodes` — многие узлы не имеют меток. Откройте их и назовите.

Дублирующиеся обрезанные этикетки не блокируют экспорт. Первая встреченная запись с меткой сохраняется, а последующие записи с такой же обрезанной меткой пропускаются.

Перед сохранением установите метки на экране [Таблица узлов](node-table.md) или на экране конфигурации узла.

## Загрузка сети

Загрузка **не** автоматически создает сеть. Он переносит одну сохраненную конфигурацию узла в [Гаечный ключ](../wrench/index.md) компьютера, которую затем вставляете в реальный узел.

1. Из [Сетевой каталог](network-directory.md) с **нет подключенной сети** используйте **Основное взаимодействие** на **ЗАГРУЗИТЬ СЕТЬ** (`Read .lnet file`), чтобы открыть страницу **ФАЙЛЫ**.
2. Используйте основное взаимодействие с файлом в столбце **ФАЙЛЫ**. Метки его узлов заполняют столбец **LABELS**.
3. Используйте первичное взаимодействие на этикетке. В столбце **PREVIEW** отображается сводная информация об этом узле — количество каналов, количество фильтров, обновления и все необходимые элементы.
4. Используйте основное взаимодействие для **КОПИРОВАТЬ В WRENCH**. Конфигурация выбранной этикетки загружается в разъем компьютера.
5. Закройте компьютер, чтобы вернуть обновленный ключ в свой инвентарь. Затем используйте **Ключ-модификатор 1 + Вторичное взаимодействие** (по умолчанию: **Shift + Щелчок правой кнопкой мыши**), чтобы вставить конфигурацию в узел. См. [Копировать и вставить](../wrench/copy-paste.md), чтобы узнать, как работает вставка.

Повторите действия для каждой метки, чтобы восстановить каждый узел сохраненной сети.

## Страница ФАЙЛЫ

- **ОБНОВИТЬ** — повторно просканировать папку, если вы добавляли или удаляли файлы вне игры.
- **ФАЙЛЫ** / **ЭТИКЕТКИ** / **ПРОСМОТР** — три столбца, описанные выше. Прокрутите колесо по столбцу файла или метки, чтобы просмотреть длинные списки.

Если папка пуста, на странице будет написано **Нет файлов .lnet**. Файл, который не удается проанализировать, сообщает **Недопустимый файл .lnet** — формат текстовый, поэтому отредактированный вручную файл с поврежденным заголовком или неверными данными буфера обмена будет отклонен.
