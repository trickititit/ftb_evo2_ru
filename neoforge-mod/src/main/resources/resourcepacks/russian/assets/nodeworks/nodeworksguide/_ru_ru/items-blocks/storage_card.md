# <a name="storage-card" />Карта памяти

Карта памяти отмечает соседний блок как часть [Сетевое хранилище](../nodeworks-mechanics/network-storage.md). Общий пул, к которому сетевые запросы, маршруты и списки в терминале инвентаризации.

<ItemImage scale="6" id="storage_card" />

## <a name="configuration" />Конфигурация

Щелкнув правой кнопкой мыши по **Карте памяти**, вы можете установить приоритет, канал и фильтры.

![](../assets/images/storage-card-gui.png)

> **Совет.** Используйте <ItemLink id="card_programmer" />, чтобы скопировать настройки карты > (необязательно также имя и канал), что позволит вам массово установить настройки карты > с помощью шаблона. > > Вы также можете использовать [`network:route()`](../lua-api/network.md#route) для массовой установки настроек карты >, даже не прикасаясь к ним.

## <a name="target-face" />Целевое лицо

Вы можете выбрать, с какой стороной соседнего блока будет общаться карта. По умолчанию карта использует лицо, на которое указывает узел, и это обычно то, что вам нужно. Переопределите его для блоков со специальными боковыми слотами, таких как печи, где верхняя часть принимает входные данные, боковая — топливо, а нижняя — выходные данные.

## <a name="channel" />Канал

В графическом интерфейсе карты памяти также имеется средство выбора каналов. См. [Выбор канала](../lua-api/channel.md#choosing-a-channel), чтобы узнать, как каналы определяют, какие сценарии, правила маршрутизации и предустановки видят эту карту.

## <a name="filters" />Фильтры

Каждую карту памяти можно настроить на прием только определенных элементов, поэтому сеть с несколькими картами направляет входящие элементы в нужное место. Свежая карта не имеет фильтров и принимает все.

### <a name="mode" />Режим

Переключатель **Режим** в графическом интерфейсе карты памяти переключает список правил между

- **Разрешить**: принимаются только элементы, соответствующие хотя бы одному правилу.
- **Запретить**: элементы, соответствующие хотя бы одному правилу, отклоняются, все остальное проходит.

Если в списке нет правил, режим не действует, но фильтры **Стекируемость** и **NBT**, приведенные ниже, по-прежнему применяются сверху. Карта принимает все только тогда, когда все три фильтра установлены по умолчанию (без правил, любая стекируемость, любой NBT).

### <a name="rules" />Правила

Каждое правило представляет собой одну строку синтаксиса фильтра, сравниваемую с элементом, пытающимся ввести карту:

| Синтаксис | Матчи |
| ----------------------- | ---------------------------------------------- |
| `minecraft:cobblestone` | точный идентификатор предмета |
| `#minecraft:logs` | каждый элемент в этом теге |
| `minecraft:*` | каждый предмет из этого мода/пространства имен |
| `/^.*_ore$/` | элементы, идентификатор которых соответствует этому регулярному выражению |
| `*` | каждый предмет/жидкость |

Вы можете добавить правила тремя разными способами:

1. Нажмите **[+ Добавить правило]** внизу списка и введите новую строку.
Автозаполнение предлагает идентификаторы и теги элементов по мере ввода.
2. Перетащите любой элемент из JEI в список правил. Идентификатор предмета становится новым правилом
3. В скриптовом терминале используйте [`network:route()`](../lua-api/network.md#route)
устанавливать правила сразу для многих карточек

### <a name="stackability-and-nbt" />Стекируемость и NBT

Два дополнительных переключателя сужают то, что карта принимает за пределами списка правил:

- **Стекируемость**: циклически переключается между вариантами **Любой** / **Только штабелируемый** / **Только нештабелируемый**.
Полезно для отделения инструментов и брони от объемных ресурсов без указания идентификатора каждого предмета.
- **NBT**: циклически переключается между вариантами **Любой** / **Есть данные** / **Нет данных**.
Предметы с НБТ (поврежденные инструменты, именные предметы, зачарованные книги) можно отделить от их первоначальных версий.

Все три настройки объединяются. Предмет попадает на карту только в том случае, если он соответствует требованиям Stackability, NBT и соответствует списку правил. Карта с `Mode: Allow`, `Stackability: Stackable only`, `NBT: No data` и правилом `#minecraft:swords` на практике ничего не принимает. Мечи не штабелируются, поэтому проверка штабелируемости отклоняет все еще до того, как будет просмотрен список правил. Выбирайте настройки, которые имеют смысл вместе.

### <a name="examples" />Примеры

**Склад булыжника**

> **Режим:** Разрешить > > **Стекируемость:** Любой > > **NBT:** Любой > > **Правила:** #c:cobblestone

Принимает любой булыжник в теге `#c:cobblestones`.

**Только нештабелируемые**

> **Режим:** Разрешить > > **Стекируемость:** Только нештабелируемый > > **NBT:** Любой > > **Правила:** *Пусто*

Карта памяти, которая принимает любые нештабелируемые предметы, не требует каких-либо правил.

## <a name="installation-and-scripting" />Установка и скриптинг

Устанавливается так же, как <ItemLink id="io_card" />. Вставьте в грань узла, касающегося блока. API сценариев идентичен карте ввода-вывода (полный набор методов см. в [КартаРучка](../lua-api/card-handle.md#inventory-cards)).

## <a name="the-difference-from-io" />Отличие от ИО

Блоки <ItemLink id="io_card" /> — это инвентари, управляемые скриптом.
Скрипты должны явно перемещать элементы в/из них. Карта памяти помещает свой блок *в* общий пул сети: `network:find` видит его,
<ItemLink id="inventory_terminal" /> и <ItemLink id="portable_inventory_terminal" /> перечисляют его, и рецепты крафта извлекают из него ингредиенты.
автоматически.
