# <a name="processing-handler" />Обработчик обработки

Блочный обработчик для рецептов [Набор обработки](./recipe_sets.md#processing-set). Добавьте один из них в сеть, привяжите его к рецепту, и [Создание процессора](./crafting_cpu.md) направит ингредиенты рецепта на вашу машину и получит выходные данные обратно без необходимости писать какие-либо Lua.

## <a name="two-sides" />Две стороны

Обработчик имеет переднюю и заднюю грань:

- **Обратная сторона**: присоединяется к родительской сети, в которой находится ваш
  <ItemLink id="crafting_core" /> и
  <ItemLink id="processing_storage" /> в прямом эфире.
- **Лицевая сторона**: закрепляет собственную **микросеть** из каналов, узлов и карт памяти. Обработчик действует как контроллер для этой стороны, поэтому <ItemLink id="network_controller" /> не требуется (или не допускается) спереди.

Подключите заднюю часть к основной сети и проложите небольшой контур трубы спереди к той машине, которая действительно выполняет рецепт.

## <a name="binding-a-recipe" />Привязка рецепта

Щелкните правой кнопкой мыши обработчик, чтобы открыть его графический интерфейс, и выберите
<ItemLink id="processing_set" /> из обработки родительской сети
Хранение. Каждый ингредиент в наборе получает свою собственную строку в графическом интерфейсе с цветом канала, а также один цвет канала для выходных данных рецепта.

## <a name="channel-routing" />Маршрутизация каналов

Обработчик использует каналы, чтобы решить, какие
<ItemLink id="storage_card" /> в микросети получает каждый элемент:

- **Входные каналы** (по одному на ингредиент, по умолчанию синий). Когда ЦП запускает поделку, каждый ввод передается на карту памяти в микросети, канал которой соответствует цвету этого ингредиента.
    - *Элементы ввода также учитывают фильтры карты памяти, если вам нужна настраиваемая маршрутизация по выражению, данным об элементе или возможности стекирования*
- **Выходной канал** (один общий цвет, по умолчанию красный). Обработчик отслеживает карты памяти в микросети с помощью этого канала и возвращает готовые выходные данные обратно в родительскую сеть.

Для примера печи в сцене выше: синяя карта памяти вверху печи получает необработанные входные данные, печь обрабатывает их, а красная карта памяти внизу собирает результат.

Разные ингредиенты могут иметь разные цвета, когда одной машине они нужны в разных слотах, например, топливо — с одной стороны, а вход — с другой.

## <a name="compared-to-a-scripted-handler" />По сравнению со скриптовым обработчиком

Обработчик обработки — это бесскриптовый эквивалент [`network:handle(...)`](../lua-api/network.md#handle). Используйте обработчик, когда рецепт «введите входные данные, извлеките выходные данные». Используйте скриптовый обработчик, когда вам нужно индивидуальное время или многоэтапные потоки.
