# <a name="auto-crafting" />Автокрафт

Авто-крафт — это то, что превращает фразу «Мне нужно 64 железные кирки» в 64 настоящие железные кирки. Вы сообщаете сети, какие рецепты существуют, сеть хранит ингредиенты, а <ItemLink id="crafting_core" /> выполняет всю работу.

## <a name="getting-it-working" />Как заставить это работать

Вам нужны четыре вещи, все в одной сети:

1. **ЦП.** Поставьте <ItemLink id="crafting_core" />, вставьте хотя бы один
   <ItemLink id="crafting_storage" /> и подключите ядро к
   <ItemLink id="node" />. См. [Создание процессора](../items-blocks/crafting_cpu.md)
   дополнительные возможности, такие как дополнительные буферы, охлаждающая жидкость и подложка.
2. **Рецепты.** Создайте каждый рецепт в
   <ItemLink id="instruction_set" /> (ванильный крафт 3×3) или
   <ItemLink id="processing_set" /> (что-нибудь еще), затем поместите их в
   <ItemLink id="instruction_storage" /> или
   <ItemLink id="processing_storage" /> и подключите его к сети.
3. **Ингредиенты.** Сырье должно быть где-то в [Сетевое хранилище](./network-storage.md). Любой сундук, подключенный к <ItemLink id="storage_card" />, засчитывается.
4. **Как задать вопрос.** Либо <ItemLink id="inventory_terminal" /> для вас.
   на который нужно нажать, или скрипт, работающий на <ItemLink id="terminal" />, который вызывает `network:craft(...)`.

Как только все четыре будут на месте, предметы, которые сеть может создать, появятся в терминале инвентаря (можно отобразить с помощью фильтров или удерживая клавишу Left-Alt, чтобы отобразить значки плюса), а `network:craft("...")` возвращает строителя вместо нуля.

## <a name="requesting-a-craft" />Запрос на поделку

### <a name="from-the-inventory-terminal" />Из терминала инвентаря

Откройте терминал, найдите предмет и `Alt+click` его. Введите количество и подтвердите. **Очередь изготовления** в верхней части терминала показывает все предметы, находящиеся в очереди. Когда поделка завершится, предмет отобразится с небольшим индикатором, и вы сможете его взять. Когда вы в следующий раз откроете терминал, он отобразится вместе с остальными элементами.

Удерживая `Alt`, вы выделяете каждый предмет, который можно изготовить автоматически, в сети, даже если его нет в наличии.

### <a name="from-a-script" />Из сценария

Скрипт может поставить поделку в очередь с помощью `network:craft` и решить, куда пойдет результат:

<LuaCode>
```lua
-- the result auto-stores into Network Storage when it's ready
network:craft("minecraft:door")
```
</LuaCode>

Или добавьте `:connect(fn)`, чтобы запустить собственный код в момент завершения поделки.

<LuaCode>
```lua
local furnace = network:get("someFurnaceCard")
network:craft("minecraft:charcoal"):connect(function(item: ItemsHandle?)
  if item then
    furnace:insert(item)
  end
end)
```
</LuaCode>

См. [network:craft](../lua-api/network.md#craft) и [РемеслоСтроитель](../lua-api/craft-builder.md) для полного API.

## <a name="cancelling-a-craft" />Отмена поделки

Щелкните правой кнопкой мыши <ItemLink id="crafting_core" />, чтобы открыть его графический интерфейс. Кнопка **"Отмена"** появляется всякий раз, когда запущен корабль. Нажатие на нее прерывает работу, возвращает все содержимое буфера в сетевое хранилище и освобождает процессор.

## <a name="processing-sets-need-a-handler" />Наборам обработки нужен обработчик

<ItemLink id="instruction_set" /> рецепты просто работают. Ванильный крафт 3x3
автономны, поэтому ЦП точно знает, как их выполнить.

<ItemLink id="processing_set" /> рецептов нет. Набор обработки *объявляет*
рецепт («8 необработанного железа становится 8 слитками необработанного железа»), но не знает, **как** на самом деле происходит это преобразование. Кто-то должен положить сырое железо в печь и вытащить слитки обратно, и этого человека называют **обработчиком**.

У вас есть два способа зарегистрировать его:

### <a name="with-a-processing-handler-block" />С блоком обработчика обработки

Добавьте <ItemLink id="processing_handler" /> в сеть и привяжите его к рецепту в графическом интерфейсе. Подключите его сзади к родительской сети, а затем проложите небольшую подсеть каналов от его передней части к любой машине, выполняющей рецепт. Процессор управляет машиной за вас, никаких сценариев не требуется. Это правильный выбор практически для любой машины, в которой «что-то в одной стороне, что-то в другой».

### <a name="with-a-scripted-handler" />Со скриптовым обработчиком

Для рецептов, требующих специального времени, условной маршрутизации или многошаговых потоков, вы можете написать обработчик Lua для <ItemLink id="terminal" />:

<LuaCode>
```lua
local furnace = network:get("someFurnaceCard")
network:handle("...", function(job: Job, inputs: InputItems)
  -- put raw iron into the top face of the furnace (like a hopper on top of the furnace)
  furnace:face("top"):insert(inputs.rawIron)
  -- wait for the output to appear by pulling from the bottom of the furnace (like a hopper again)
  job:pull(furnace:face("bottom"))
end)
```
</LuaCode>

Если вы попытаетесь автоматически создать что-то, для чего нужен набор обработки, а обработчик не зарегистрирован, создание завершится неудачно с сообщением о том, в каком рецепте отсутствует обработчик.

Полный шаблон см. в [network:handle](../lua-api/network.md#handle), [Работа](../lua-api/job.md) и [Инпутитемс](../lua-api/input-items.md).

## <a name="when-something-goes-wrong" />Когда что-то идет не так

Если корабль терпит неудачу, <ItemLink id="crafting_core" /> начинает испускать частицы красной пыли в виде пульсирующего облака вокруг блока. Он продолжает пульсировать до тех пор, пока вы либо не откроете графический интерфейс ядра и не устраните ошибку, либо не начнете новую работу, которая увенчается успехом. Когда что-то не так, сначала просканируйте красную пыль. Само ядро ​​— это самый быстрый способ определить, какой процессор жалуется.

![](../assets/images/crafting_cpu_erroring.png)

Конкретные сообщения, которые сообщает процессор:

| Сообщение | Что это значит |
| -------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Крафт ЦП по адресу (x, y, z) не формируется | Ядро не имеет <ItemLink id="crafting_storage" />, касающегося его, или Ядро не подключено к сети.                                                     |
| Недостающие ингредиенты: N× предмет, ... Рецепт отсутствует, и его недостаточно на складе.                               | В сети нет возможности получить эти предметы, и ни один рецепт их не производит. Сложите их в сетевой сундук или напишите рецепт.                        |
| Обработчик не зарегистрирован для: X. Добавьте вызов `network:handle("recipe", ...)` в скрипт подключенного Терминала.     | X — это рецепт набора обработки без обработчика Lua для его управления. См. [Наборам обработки нужен обработчик](./autocrafting.md#processing-sets-need-a-handler) выше. |
| Для крафта требуется N уникальных типов предметов, процессор вмещает только M. Добавьте больше буферных блоков или уровней улучшения.                    | Счетчик <ItemLink id="crafting_storage" /> вашего процессора не может содержать достаточного количества различных типов предметов для промежуточных продуктов этого ремесла. Добавьте буферы.                      |
| Для крафта требуется до N предметов одного типа в буфере, процессор вмещает только M. Обновите уровни буфера или добавьте больше блоков. | Та же проблема, другая ось: один шаг ремесла переполнил бы емкость буфера каждого типа.                                                            |
