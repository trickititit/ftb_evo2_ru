# <a name="the-storage-bus" />Автобус хранения

<GameScene zoom="8" background="transparent">
<ImportStructure src="../assets/blocks/storage_bus.snbt" />
</GameScene>

Вы когда-нибудь хотели *сохранить* свой сундук-монстр вместо того, чтобы заменить его чем-то разумным? Представляем складской автобус!

Шина хранения превращает инвентарь, к которому она прикасается, в [сетевое хранилище](../ae2-mechanics/import-export-storage.md). Он делает это, позволяя сети видеть содержимое этого инвентаря, а также отправляя и извлекая данные из этого инвентаря, чтобы удовлетворить потребности [устройства](../ae2-mechanics/devices.md), которые отправляют данные в сетевое хранилище и извлекают из него.

Благодаря философии AE2 возникающей механики посредством взаимодействия функций [устройства](../ae2-mechanics/devices.md), вам не обязательно *должно* использовать шину хранения для *хранения*. Используя [подсети](../ae2-mechanics/subnetworks.md), чтобы сделать шину хранения (или несколько шин хранения) *единственным* хранилищем в сети, вы можете использовать ее в качестве источника или места назначения для передачи элементов. Примеры см. в ["трубная подсеть"](../example-setups/pipe-subnet.md).

ВАЖНОЕ ПРИМЕЧАНИЕ. Большие оптимизированные инвентари, такие как ящики, — это хорошо, но большие *неоптимизированные* инвентари со множеством слотов, такие как огромные сундуки, ужасны для производительности при использовании с шинами хранения.

Они [части кабеля](../ae2-mechanics/cable-subparts.md).

## <a name="filtering" />Фильтрация

По умолчанию шина сохранит все. Элементы, вставленные в слоты фильтров, будут действовать как белый список, позволяя сохранять только эти конкретные элементы.

Предметы и жидкости можно перетаскивать в слоты из JEI/REI, даже если у вас на самом деле нет ни одного из этих предметов.

Щелкните правой кнопкой мыши контейнер с жидкостью (например, ведро или резервуар с жидкостью), чтобы установить эту жидкость в качестве фильтра вместо ведра или бака.

## <a name="priority" />Приоритет

Приоритеты можно установить, щелкнув гаечный ключ в правом верхнем углу графического интерфейса. Товары, поступающие в сеть, начинаются с хранилища с наивысшим приоритетом в качестве первого пункта назначения. В случае, если два хранилища имеют одинаковый приоритет, и если одно из них уже содержит элемент, они предпочтут это хранилище любому другому. Любые отфильтрованные хранилища будут считаться уже содержащими элемент, если они находятся в той же группе приоритета, что и другие хранилища. Предметы, удаляемые из хранилища, будут удалены из хранилища с наименьшим приоритетом. Эта система приоритетов означает, что по мере того, как элементы вставляются и удаляются из сетевого хранилища, хранилища с более высоким приоритетом будут заполняться, а хранилища с более низким приоритетом будут опорожняться.

## <a name="settings" />Настройки

*   Автобус можно разделить (отфильтровать) на то, что в данный момент находится в соседнем инвентаре.
*   Сети можно запретить или разрешить видеть в соседнем инвентаре предметы, которые автобус не может извлечь. Например, шина хранения не может извлекать элементы из среднего входного слота <ItemLink id="inscriber" />.
*   Шина может фильтровать как вставку, так и извлечение или только вставку.
*   Шина может быть двунаправленной, только для вставки или только для извлечения.

## <a name="upgrades" />Обновления

Шина хранения поддерживает следующие [обновления](upgrade_cards.md):

*   <ItemLink id="capacity_card" /> увеличивает количество слотов для фильтров.
*   <ItemLink id="fuzzy_card" /> позволяет шине фильтровать по уровню повреждения и/или игнорировать элемент NBT.
*   <ItemLink id="inverter_card" /> переключает фильтр из белого списка в черный список.
*   <ItemLink id="void_card" /> аннулирует вставленные предметы, если прикрепленный инвентарь полон. Полезно для предотвращения резервного копирования ферм. Будьте осторожны при разделении шины хранения данных!
